# Preview Deploy Lab

Маленький стенд на React + Vite, чтобы на практике разобраться, как устроены
preview-деплои Vercel.

Идея простая: приложение рассказывает о себе само — из какого окружения оно
собрано, из какой ветки и коммита, по каким адресам доступно и что видит
серверная функция. Открываешь preview и прод в двух вкладках и видишь разницу
глазами.

## Первым делом: включить системные переменные

Без этого страница почти пустая — она честно об этом напишет и покажет шаги.

1. Проект в дашборде Vercel → **Settings**
2. В левом меню → **Environment Variables**
3. Чекбокс **«Enable access to System Environment Variables»** — он на этой же
   странице, над списком переменных
4. **Deployments** → ⋯ у последнего деплоя → **Redeploy**

Последний шаг обязателен: переменные вшиваются в бандл в момент сборки, поэтому
уже собранный деплой сам по себе не поумнеет.

Почему это вообще нужно. Vite отдаёт в браузер только переменные с префиксом
`VITE_`. Vercel умеет добавлять этот префикс к своим системным переменным
(`VERCEL_ENV` → `VITE_VERCEL_ENV`), но делает это по чекбоксу. Серверной функции
в `api/` чекбокс не нужен — она читает `process.env` напрямую и видит всё всегда.

## Как читать страницу

**Шапка и первый блок** — где ты находишься. Бейдж: оранжевый PREVIEW, зелёный
PRODUCTION. Ниже — ветка, коммит и когда собрано.

**Маркер** — то единственное, что нужно менять в эксперименте (`src/marker.js`).
Заголовок, текст и цвет полосы. Поменял в ветке — на preview новый, на проде
старый.

**Три адреса** — суть механизма. У каждого деплоя их одновременно несколько:

| Адрес | Что показывает |
|---|---|
| `test-project-<hash>-<scope>.vercel.app` | Один конкретный коммит, навсегда. Такую ссылку кидают в чат |
| `test-project-git-<ветка>-<scope>.vercel.app` | Последний коммит ветки. Ссылка та же, содержимое обновляется |
| `test-project.vercel.app` | Прод. Меняется только при мёрже в `main` |

Кнопка «Открыть прод и сравнить» появляется на preview: жмёшь — и рядом
открывается боевая версия.

**Два блока про переменные** — одно и то же, но в разные моменты времени. Левый
вшит в JS-файл при сборке, правый прочитан функцией в момент запроса. Отсюда
правило: поменял переменную в настройках — нужен передеплой, иначе фронтенд
будет показывать старое значение.

**Чеклист** — что делать по шагам и что должно произойти на каждом.

## Эксперимент

```bash
git checkout -b experiment/red-banner
# поменять MARKER в src/marker.js
git commit -am "Красный маркер"
git push -u origin experiment/red-banner
```

В Vercel появится отдельный деплой со статусом **Preview**. Прод при этом не
шелохнётся. Откроешь pull request — бот повесит в него комментарий со ссылкой.
Смёржишь — тот же код уедет в production.

### Разные переменные для preview и прода

В Settings → Environment Variables заведи `MY_GREETING` и задай ей разные
значения, выбрав в форме галочками сначала Preview, потом Production. Функция
`/api/info` вернёт то значение, которое положено её окружению — видно прямо на
странице, в поле `customGreeting`.

Так же разводят и боевые секреты: preview ходит в тестовую базу, прод — в
боевую, код при этом один и тот же.

## Локальный запуск

```bash
npm install
npm run dev
```

Бейдж покажет LOCAL DEV, блок про серверную функцию — заглушку: Vite не
поднимает `api/`. Чтобы получить функции и переменные локально, нужен Vercel CLI
(`vercel dev`).

Чтобы посмотреть, как страница выглядит на настоящем preview, не деплоя, можно
подсунуть переменные руками — создай `.env.local` (он в `.gitignore`):

```
VITE_VERCEL_ENV=preview
VITE_VERCEL_GIT_COMMIT_REF=experiment/red-banner
VITE_VERCEL_GIT_COMMIT_SHA=fa1eade47b73733d6312d5abfad33ce9e4068081
VITE_VERCEL_URL=test-project-abc123.vercel.app
VITE_VERCEL_BRANCH_URL=test-project-git-experiment-red-banner.vercel.app
VITE_VERCEL_PROJECT_PRODUCTION_URL=test-project.vercel.app
```

## Структура

| Файл | Зачем |
|---|---|
| `src/marker.js` | Точка эксперимента: заголовок, текст, цвет |
| `src/deployInfo.js` | Читает `VITE_VERCEL_*`, вшитые в бандл при сборке |
| `src/Addresses.jsx` | Три адреса и чем они отличаются |
| `src/SetupHint.jsx` | Инструкция, если чекбокс не включён |
| `src/ServerProbe.jsx` | Запрос к `/api/info` — что видно на рантайме |
| `src/Checklist.jsx` | План эксперимента |
| `api/info.js` | Серверная функция |
