# Preview Deploy Lab

Маленький стенд на React + Vite, чтобы на практике разобраться, как устроены
preview-деплои Vercel.

Приложение показывает само себя: из какого окружения оно собрано, из какой ветки
и коммита, что видит серверная функция и когда был сделан билд. Открыв два адреса
рядом — прод и preview — видно, чем они отличаются.

## Что внутри

| Файл | Зачем |
|---|---|
| `src/marker.js` | Точка эксперимента: меняешь заголовок и цвет — правка едет в preview |
| `src/deployInfo.js` | Читает системные переменные Vercel, вшитые в бандл на этапе сборки |
| `api/info.js` | Серверная функция: те же переменные, но на рантайме |
| `src/Checklist.jsx` | План эксперимента с галочками |
| `src/Playground.jsx` | Живой кусок UI, чтобы было что менять в ветках |

## Локальный запуск

```bash
npm install
npm run dev
```

Бейдж покажет `LOCAL DEV`, блок с серверной функцией — ошибку: Vite не запускает
функции из `api/`. Чтобы поднять их локально, нужен `vercel dev` из Vercel CLI.

## Как завести на Vercel

1. Импортировать репозиторий в Vercel. Фреймворк определится сам (Vite),
   команда сборки `npm run build`, папка `dist`.
2. Зайти в Settings → Environment Variables и включить
   **Automatically expose System Environment Variables**. Без этого блок
   «что видит сборка» останется пустым: Vite подхватывает только переменные с
   префиксом `VITE_`, а Vercel добавляет этот префикс именно по тумблеру.
3. Первый деплой с `main` уедет в production.

## Эксперимент

```bash
git checkout -b experiment/red-banner
# поменять MARKER в src/marker.js
git commit -am "Красный маркер"
git push -u origin experiment/red-banner
```

Дальше:

* В дашборде Vercel появится отдельный деплой со статусом **Preview** и своим URL.
* Откроешь pull request — бот повесит в него комментарий со ссылкой на preview.
* На preview будет новый маркер, на проде — старый. Прод не трогается, пока PR не смёржен.
* У каждого коммита свой неизменяемый URL вида `test-project-<hash>-<scope>.vercel.app`,
  плюс есть «живой» URL ветки, который всегда указывает на её последний коммит.
* Смёржишь PR в `main` — тот же код уедет уже в production.

### Переменные окружения на preview

В Settings → Environment Variables можно завести `MY_GREETING` с разными значениями
для Preview и Production. Функция `/api/info` вернёт то значение, которое положено
её окружению — видно прямо на странице.

Так же работают и боевые секреты: preview-деплой имеет смысл сажать на тестовую
базу, а не на продовую, просто разведя переменные по окружениям.
